Архитектура системы
===================

Система реализована как монолит с модульной структурой
(см. архитектурную диаграмму в курсовой работе).

Слой представления
------------------

Два веб-интерфейса (SPA), общающихся с сервером по REST:

* Чат-интерфейс пользователя (``static/index.html``).
* Админ-панель (``static/admin.html``).

Слой провайдеров (бизнес-сервисы)
---------------------------------

* :mod:`app.services.chat_service` — оркестратор «вопрос → RAG → LLM
  → ответ». Содержит классы :class:`~app.services.chat_service.RAGService`
  (семантический поиск в ChromaDB) и
  :class:`~app.services.chat_service.ChatService` (интеграция с Gemini).
* :mod:`app.services.feedback_service` — обработка оценок ответов бота.
* :mod:`app.services.admin_service` — CRUD по справочникам НПА,
  типовых сценариев, пользователей и конфигурации, а также
  агрегация статистики.
* :mod:`app.services.auth_service` — аутентификация и авторегистрация
  с хешированием паролей через bcrypt.

Слой данных
-----------

* PostgreSQL / SQLite — реляционные данные.
* ChromaDB — векторные представления фрагментов НПА.
* Внешний LLM API (Google Gemini) — генерация ответов.

Безопасность
------------

* Пароли хешируются bcrypt-ом
  (:mod:`app.core.security`).
* Авторизация по ролям через FastAPI-зависимость
  :func:`app.core.deps.require_admin`.
* Идентификация запроса по HTTP-заголовку ``X-User-Id``.
  Для production следует мигрировать на JWT-токены.
