# ЮрКонсультант ИИ

**ЮрКонсультант ИИ** — это веб-система для получения первичной юридической информации с помощью чат-бота.  
Пользователь может задать юридический вопрос в свободной форме, получить справочный ответ, посмотреть историю консультаций и оставить оценку качества ответа.

Проект разрабатывается как учебная информационная система в рамках дисциплины **«Системная и программная инженерия»**.

> ❗ Система не заменяет профессионального юриста, адвоката или официальную юридическую консультацию. Ответы чат-бота носят справочный характер. В сложных, спорных, срочных или финансово значимых ситуациях рекомендуется обращаться к специалисту.

---

## О проекте

Система предназначена для пользователей, которым нужно быстро разобраться в юридической ситуации, получить общее объяснение, понять возможный порядок действий или расшифровать юридический термин простым языком.

Основная идея проекта — объединить веб-интерфейс, базу правовых материалов, RAG-поиск и языковую модель для формирования понятных юридических ответов.

## Основные возможности

### Для пользователя

- авторизация в системе;
- отправка юридического вопроса в свободной форме;
- получение ответа от чат-бота;
- использование правового контекста при формировании ответа;
- просмотр истории консультаций;
- открытие прошлых диалогов;
- объяснение юридических терминов простым языком;

- оценка ответа бота;
- отправка комментария к ответу.

### Для администратора

- вход в административную панель;
- управление правовыми материалами;
- управление типовыми юридическими ситуациями;
- управление пользователями;
- настройка поведения чат-бота;
- просмотр статистики системы;
- анализ качества ответов по обратной связи.

## Основные модули

### `main.py`

Точка входа FastAPI-приложения.  
В файле создаётся объект приложения, подключаются роутеры, CORS, статические файлы, пользовательская страница и административная панель.

### `database.py`

Модуль подключения к базе данных.  
Отвечает за создание SQLAlchemy engine, фабрики сессий `SessionLocal`, базового класса `Base` и зависимости `get_db`.

### `models.py`

Содержит ORM-модели базы данных:

- `User`;
- `Conversation`;
- `Message`;
- `Feedback`;
- `LegalMaterial`;
- `TypicalSituation`;
- `BotConfig`.

### `schemas.py`

Содержит Pydantic-схемы для проверки входящих запросов и формирования ответов API.

### `security.py`

Содержит функции безопасности для хэширования и проверки паролей.

### `chat_service.py`

Отвечает за работу чат-пайплайна:

1. поиск релевантного контекста в ChromaDB;
2. формирование промпта;
3. обращение к Google Gemini;
4. получение ответа;
5. сохранение результата в истории диалога.

### `admin_service.py`

Содержит бизнес-логику административной части: управление НПА, типовыми ситуациями, пользователями, конфигурацией бота и статистикой.

### `feedback_service.py`

Отвечает за сохранение пользовательской оценки ответа бота и комментария.

## Быстрый запуск

### 1. Клонировать репозиторий

```bash
git clone ссылка-на-репозиторий
cd название-репозитория
```

### 2. Создать виртуальное окружение

```bash
python -m venv venv
```

### 3. Активировать виртуальное окружение

Для Windows:

```bash
venv\Scripts\activate
```

Для Linux / macOS:

```bash
source venv/bin/activate
```

### 4. Установить зависимости

```bash
pip install -r requirements.txt
```

### 5. Создать файл `.env`

В корне проекта необходимо создать файл `.env` и указать переменные окружения.

Пример:

```env
DATABASE_URL=sqlite:///./app.db
GEMINI_API_KEY=your_gemini_api_key
```

### 6. Заполнить базу начальными данными

```bash
python seed.py
```

### 7. Запустить приложение

```bash
uvicorn app.main:app --reload
```

После запуска приложение будет доступно по адресу:

```text
http://127.0.0.1:8000
```

## Пользовательский сценарий

1. Пользователь открывает веб-приложение.
2. Проходит авторизацию.
3. Задаёт юридический вопрос.
4. Система сохраняет сообщение пользователя.
5. Выполняется поиск релевантного правового контекста.
6. Языковая модель формирует ответ.
7. Ответ сохраняется в истории консультации.
8. Пользователь может оценить ответ и оставить комментарий.

## Административный сценарий

1. Администратор открывает страницу `/admin`.
2. Проходит авторизацию.
3. Управляет правовыми материалами.
4. Добавляет или редактирует типовые ситуации.
5. Настраивает поведение бота.
6. Просматривает статистику и качество ответов.
7. Анализирует обратную связь пользователей.

## Ограничения системы

Система имеет ряд ограничений:

- ответ чат-бота не является юридическим заключением;
- результат зависит от полноты и точности вопроса;
- система может не учитывать все детали конкретного дела;
- сложные юридические ситуации требуют обращения к специалисту;
- перед подачей документов или обращением в суд информацию необходимо дополнительно проверить.
